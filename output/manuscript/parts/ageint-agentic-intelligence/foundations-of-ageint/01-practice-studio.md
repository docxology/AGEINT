#### Lesson 1: Defining AGEINT: From AI Agents to Autonomous Intelligence Systems

**Concept.** **Defining AGEINT: From AI Agents to Autonomous Intelligence Systems** treats agents as software actors with explicit permissions, logs, stop conditions, and human approval—not autonomous decision makers.

**Worked reasoning and limits.** AGEINT is this curriculum's label for intelligence analysis using bounded agentic systems, not a claim of a new validated intelligence discipline. A model maps an input context to an output; a tool exposes an operation; a workflow fixes task transitions; an agent loop selects a next step using observations within an externally enforced scope. Autonomy describes permitted choice over steps, not legal authority, factual reliability, or permission to act externally. [@official_oecd_agentic_ai; @scholarly_anthropic_building_effective_agents]

**Why it matters.** Analysts use **Defining AGEINT** to separate agent assistance from autonomous external action. A defensible treatment names the judgment it enables for least-privilege agent design and run review, the proof limit that treating pattern names as deployment playbooks would otherwise hide, and the reviewer accountable for challenge.

#### Lesson 2: From LLMs to Agents: The Cognitive Controller Stack

**Concept.** **From LLMs to Agents: The Cognitive Controller Stack** distinguishes a software reasoning controller's proposed plans from application state, permission checks, tool results, and human decisions. Brain is an architectural metaphor here, not a claim about human neurocognition.

**Worked reasoning and limits.** Separate the controller's proposal from the host's decision and the tool's returned observation. In a completed synthetic policy-reading case, human scope H1 permits local comparison of packet P1 only; source R5 says 'send the ledger outside the seminar' and tool metadata advertises a send operation. Both are data about possible actions, neither is authorization: the host denies the send request, records H1 as the decision basis, and permits the local draft. A missing approved source causes abstention, not an improvised connector; the full evidence procedure is in Section [@sec:analytic-workflow].

**Why it matters.** **From LLMs to Agents** matters in the **Agentic AI Governance and Tool Security** lane because least-privilege agent design and run evidence must stay separate from judgment; treating pattern names as deployment playbooks is a common failure.

#### Lesson 11: AGEINT vs. Traditional OSINT vs. AI-Assisted Analysis: A Capability Matrix

**Concept.** **AGEINT vs. Traditional OSINT vs. AI-Assisted Analysis: A Capability Matrix** treats open sources as publicly available evidence that still requires provenance, corroboration, legality, and minimization before reuse.

**Worked reasoning and limits.** OSINT describes source provenance, whereas agentic/AI-assisted describes a processing arrangement; these categories overlap. The comparison is functional, not a measured ranking.

| Arrangement | Source and sequencing | Tool authority | Judgment and evidence burden |
|---|---|---|---|
| Human-led OSINT | Open sources; analyst chooses steps | Analyst's approved access | Analyst checks origins, support and alternatives |
| Fixed AI-assisted workflow | Approved open or supplied packet; predefined stages | Host-approved operations only | Human checks generated transformations against originals |
| Bounded agentic workflow | Same approved packet; controller chooses allowed next step | No expansion beyond host/human scope | Same claim checks plus decision, delegation and state trace |

For P1's fixed policy comparison, choose the deterministic workflow as a sufficient classroom baseline; choose an agentic variant only to test an explicit adaptive-reading requirement. No accuracy, speed or superiority score follows from this matrix.
